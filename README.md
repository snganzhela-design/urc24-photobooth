# URC24 фотозона «Стань пилотом»

Киоск на отдельном ПК: гость жмёт USB-кнопку → вебкамера делает кадр → ИИ надевает белый
комбинезон Unigeniq → кадр в рамке URC24 показывается на экране с QR для скачивания.

**Демо-стенд: https://snganzhela-design.github.io/urc24-photobooth/**

Демо — та же страница киоска, но без сервера: открывается с телефона или ПК, снимает кадр
камерой и оформляет его в карточку пилота. Чего в нём нет и быть не может, потому что
GitHub Pages раздаёт только статику: примерки комбинезона (ИИ живёт на сервере, ключ в браузер
не выносится), загрузки кадра и QR со ссылкой на фото — вместо QR-скачивания кнопка «Сохранить
кадр», а сам QR ведёт на программу URC24. Кадр никуда не отправляется и остаётся в браузере гостя.

Сборка демо: `node scripts/make-pages-demo.mjs` (`public/` → `docs/`), локальный просмотр —
`node scripts/serve-docs.mjs`. Ветка `main` при push публикуется на Pages автоматически.

## Как устроено

- `server.mjs` — локальный сервер (127.0.0.1:3777): архив кадров `shots/{id}/`, вызов ИИ,
  QR, очередь загрузки готовых кадров на `api.unigeniq.com` (маркеры в `shots/pending/`).
- `public/` — страница киоска (`index.html`, `kiosk.js`, `kiosk.css`) и панель оператора (`/admin`).
  Композиция рамки — на `<canvas>` в браузере, серая обработка как у карточек пилотов на лендинге.
- `lib/ai.mjs` — Gemini-формат через шлюз ProxyAPI (без VPN) + запасной OpenAI-формат;
  два входных изображения: кадр гостя + `assets/reference-suit.jpg` (торс пилота без лица).
- `lib/prompt.mjs` — промты A/B. Правятся по результатам смоука.
- Бэкенд (репо `backend`): `POST /api/urc24/photo-booth` (bearer `URC24_BOOTH_TOKEN`),
  страница `GET /urc24/photo/{id}`, файл `GET /urc24/photo/{id}.jpg`, очистка `urc24:purge-booth-photos`.

## Установка на ПК фотозоны (Windows)

1. Node.js 20+ (nodejs.org, LTS), Chrome или Edge.
2. Скопировать папку `photobooth/` (без `node_modules`), в ней `npm install`.
3. `copy .env.example .env`, вписать `AI_API_KEY` (ProxyAPI) и `UPLOAD_TOKEN` (тот же, что
   `URC24_BOOTH_TOKEN` на сервере).
4. Проверка ИИ без камеры: положить любой портрет в `smoke-in/` и
   `node scripts/smoke-ai.mjs smoke-in\guest.jpg` → результат в `smoke-out/`. Обе папки
   не попадают в репозиторий: там фотографии живых людей.
5. `start.cmd` — поднимает сервер и Chrome в киоске. `install-autostart.cmd` — автозапуск после
   входа + запрет сна/гашения экрана (автологин Windows включить через `netplwiz`).
6. Панель оператора: `Ctrl+Shift+A` на экране киоска или `http://127.0.0.1:3777/admin`.

## Обновление на ПК фотозоны

1. Остановить киоск: `Alt+F4` на экране, затем закрыть свёрнутое окно `urc24-booth-server` на
   панели задач. Окно — это цикл перезапуска сервера: если его оставить, новый `start.cmd` не
   займёт порт 3777 и дальше будет работать старый код.
2. Обновить файлы. Папка — клон git: `git pull --ff-only`. Папка скопирована: заменить файлы
   из репозитория, не трогая `.env`, `shots/`, `logs/`, `runtime.json`, `chrome-profile/`,
   `node_modules/`. `npm install` — только если в `package.json` поменялись `dependencies`.
3. `start.cmd` (или перезагрузить ПК, если стоит автозапуск). Проверка — панель оператора:
   строка загрузки «ок», плитки «В очереди» и «Отвергнуто».

## Кнопка

Любая USB-«big button» на HID-клавиатуре (шлёт Space/Enter — подходит любая клавиша).
Автоповтор при зажатии игнорируется, повторное нажатие во время обработки — тоже.
Тап по экрану/клик мышью — дубль кнопки.

## Отказы

| Что случилось | Что увидит гость | Что делать оператору |
|---|---|---|
| ИИ отказал / таймаут | Кадр в рамке без комбинезона + QR | Ничего; если подряд — «Тест ИИ» в панели |
| 401/402 от шлюза (ключ/баланс) | Кадры без ИИ | Пополнить ProxyAPI → «Сбросить блокировку ИИ» |
| Нет интернета | Кадр + QR; страница по QR «ещё в пути» | Ничего: очередь дозагрузит сама каждые 30 с |
| Сервер отверг кадр (400/413/415/422) | Этот QR остаётся «ещё в пути» | Ничего: кадр уходит в `shots/failed/{id}.json` (код и причина), очередь идёт дальше. Вернуть в очередь — переложить json в `shots/pending/` |
| Сервер не принял токен или адрес (401/403/404/405) | Кадр + QR; страницы «ещё в пути» | В панели красное «загрузка стоит». Сверить `UPLOAD_TOKEN`/`UPLOAD_URL` в `.env`, перезапустить сервер — очередь дозагрузится сама, кадры не теряются |
| Нет камеры | Красная плашка внизу | Переткнуть USB; в панели выбрать камеру |
| Чёрный экран / завис | — | F5; если не помогло — Alt+F4 и снова `start.cmd` |

Логи: `logs/booth-YYYY-MM-DD.jsonl` (стадии по каждому кадру), `logs/server-restarts.log`.

Тесты очереди загрузки (подставной fetch, сеть не нужна): `npm test`.
